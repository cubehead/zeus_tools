# Zeus Tools 跨平台字符串识别与格式化工具——需求计划

> 文档状态：初始产品基线；实现状态以第 12 节和发布检查清单为准
>
> 目标平台：Windows、macOS
>
> 发布方式：个人使用、开源
>
> 数据策略：完全本地离线

当前实现与完整产品基线的差距见根目录 README 的
[Alpha limitations](../README.md#alpha-limitations)；未通过的发布门槛不会因核心功能已实现而自动勾选。

## 1. 产品定义

一句话描述：一款面向开发者的轻量桌面工具，用户粘贴或输入字符串后，工具自动识别内容类型，并在下方完成格式化、解码、语法高亮或表格化展示；同时提供摘要与 HMAC 等手动计算能力。

### 1.1 目标用户

- 主要用户：后端、前端、客户端、测试和运维开发者。
- 决策者与使用者：个人开发者本人。
- 高频场景：查看接口响应、调试配置、检查日志片段、阅读编码后的参数、预览 CSV 数据。

### 1.2 用户痛点

- JSON、XML、YAML、CSV 需要在多个网站或编辑器插件间切换。
- 计算 MD5、SHA 或 HMAC 时，经常还要打开命令行或不可信的在线网站。
- 在线格式化工具可能接触 Token、业务数据或内部接口响应，存在隐私顾虑。
- 用户经常无法立即判断字符串是结构化数据、Base64 还是 URL Encode。
- 格式错误时，现有工具通常只提示“解析失败”，缺少明确位置和原因。

### 1.3 产品目标

- 做到“粘贴即读”：自动识别、自动处理、立即展示结果。
- 所有内容均在本机处理，断网可用，不上传用户数据。
- 对 10 MB 以内的常见开发数据保持稳定、流畅。
- 同一界面覆盖结构化文本、编码字符串和 CSV 表格预览。
- 常见摘要和 HMAC 可直接基于当前输入手动计算，无需把敏感内容发往在线工具。

### 1.4 非目标

- MVP 不做账号、云同步、团队协作或付费功能。
- 不监听系统剪贴板。
- 不做多标签页、项目空间、目录管理或完整代码编辑器。
- 不自动递归解码多层编码。
- 不在 MVP 支持 SQL 格式化、代码生成、接口请求或 AI 解释。

## 2. 核心用户流程

1. 用户启动应用，看到上下双栏单窗口。
2. 用户在上方输入框粘贴或手动输入字符串。
3. 系统在短暂防抖后自动判断内容类型和识别置信度。
4. 系统在工具栏显示识别类型，例如 `JSON`、`Base64 → JSON` 或 `CSV`。
5. 下方根据类型展示：
   - JSON、XML、YAML：格式化文本与语法高亮。
   - CSV：表格预览。
   - Base64、URL Encode：自动解码一层；若结果是结构化数据，再格式化并高亮。
6. 用户检查结果或错误提示，并复制结果。
7. 自动处理不会递归解码；需要进一步解码时，用户每次手动执行“再解一层”，
   原始输入保持不变，并在状态栏看到完整处理链。
8. 用户也可从“计算”菜单选择摘要或 HMAC；HMAC 需要额外填写密钥，结果显示为 Hex 或 Base64。

## 3. 自动识别规则

### 3.1 原则

- 原始输入永不被自动覆盖。
- 高置信度结果自动处理；低置信度结果只提供候选类型和手动操作入口。
- 一次输入最多自动执行一层 Base64 或 URL Decode。
- 格式化不计入“解码层数”：例如 Base64 解码得到 JSON 后，可以继续自动格式化 JSON。
- 用户可手动切换识别类型；手动选择在当前输入未发生实质变化前保持有效。

### 3.2 建议识别优先级

1. JSON 严格解析。
2. MongoDB Shell/BSON：规范化单引号字符串与未加引号标识符键，并替换白名单构造器后，完整结构必须是合法 JSON；输出保留类型的 Extended JSON，不执行 JavaScript。
3. JWT：严格三段式 Base64URL，Header/Payload 均为 JSON；只查看内容，不验证签名。
4. XML 严格解析。
5. URL Encode：包含有效百分号编码，且解码能产生可读 UTF-8 内容。
6. Base64：满足合法字符、长度和填充规则，且解码结果为可读文本或受支持结构化数据；
   `;base64` 标记明确的 Data URL 可安全预览二进制结果。
7. YAML：通过安全解析器解析，并排除过于普通的单行纯文本。
8. CSV：多行、分隔符稳定、列数基本一致。
9. 普通文本。

若多个类型同时成立，界面显示最高置信度结果，并提供其他候选类型供用户切换。

## 5. 关键界面与状态

### 5.1 主界面

- 顶部：应用标题；右上角为主题图标、语言下拉列表和清空入口。
- 上半区：可粘贴和手动编辑的多行原始输入。
- 中间上下文操作带：位于原文与结果之间。最左显示自动识别类型；随后显示该类型的默认及专属操作；分隔线后固定显示 Encode、大小写等通用操作。`B64 Encode` 和 `URL Encode` 不因输入类型隐藏；JSON 示例为 `JSON / Format / Minify / Escape | B64 Encode / URL Encode / Upper / Lower`。
- 摘要入口：位于通用操作末尾，以独立展开/收起符号打开摘要与 HMAC 行。
- 下半区：只读富文本结果或虚拟化 CSV 表格。
- 底部：简短状态、搜索输入、大小写/正则开关、匹配跳转与复制；不重复展示“仅本地处理”。

### 5.2 手动计算面板

- 计算类别：摘要、HMAC。
- 摘要/校验和算法：CRC32、MD5、SHA-1、SHA-256、SHA-384、SHA-512。
- HMAC 算法：HMAC-MD5、HMAC-SHA1、HMAC-SHA256、HMAC-SHA384、HMAC-SHA512。
- 消息来源：原始输入或当前处理结果，默认原始输入。
- HMAC 密钥：默认遮罩显示，可临时切换可见；不得写入历史或日志。
- 输出格式：小写 Hex、大写 Hex、Base64。
- MD5 与 SHA-1 必须展示弱算法警告，但允许用于对接旧系统和校验已有值。

### 5.3 必须覆盖的状态

- 空状态：提示“粘贴或输入 JSON、XML、YAML、CSV 或编码字符串”。
- 检测中：仅对较大内容显示轻量进度，不阻塞输入。
- 成功：显示识别类型、处理结果和耗时。
- 低置信度：保留普通文本结果，同时展示候选操作。
- 解析失败：保留原文，显示错误位置、原因和手动类型切换入口。
- 二进制 Base64：显示字节数与 Hex 预览，不直接渲染乱码；可识别的常见格式显示
  类型并建议匹配扩展名，未知格式回退 `.bin`，导出始终保存原始字节；仅当输入是
  Base64 Data URL 且解码魔数确认为 PNG/JPEG 时直接显示内存图片预览，伪造 MIME
  或普通 Base64 图片不触发自动预览；摘要显示可解析的像素尺寸，无法解析尺寸或超过
  预览尺寸/总像素限制的图片只保留摘要与原始字节导出。
- 超过 10 MB：明确提示超出 MVP 保证范围，允许继续尝试或清空，不直接崩溃。
- 搜索状态：显示搜索词、匹配总数、当前序号、大小写/正则开关和无效正则错误。

## 6. 数据、隐私与安全

- 输入、输出及解析过程不得离开本机。
- MVP 默认不保存输入历史、最近内容或剪贴板内容。
- 允许持久化非内容型偏好设置；当前仅保存主题与界面语言选择。
- 不记录用户原文到日志、崩溃报告或分析事件。
- 日志仅允许记录应用版本、功能类型、耗时和错误代码，不包含内容片段。
- HMAC 密钥只存在于当前计算会话的内存中，面板清空或应用退出后不得恢复。
- MD5 和 SHA-1 仅作为兼容性工具，不得在界面文案中推荐用于密码存储、签名或新的安全设计。
- YAML 必须使用安全解析模式，禁止执行自定义对象构造或脚本。
- XML 解析需禁用外部实体和外部资源加载，避免 XXE 和本地文件泄露。
- 开源仓库需包含隐私说明、许可证、构建方式和安全问题报告渠道。

## 7. 性能与质量标准

以普通近五年开发者电脑作为参考设备：

- 应用冷启动目标不超过 2 秒。
- 1 MB 以内内容从粘贴到结果展示目标不超过 300 ms。
- 10 MB 以内内容从粘贴到首次可用结果目标不超过 2 秒。
- 大内容解析不得长时间阻塞输入或拖动窗口；需要可取消并丢弃过期任务。
- CSV 表格必须使用行列虚拟化，避免一次渲染全部单元格。
- 连续快速输入时，只展示最后一次输入对应的处理结果。
- MVP 发布前覆盖典型、边界、错误和恶意样例；核心解析流程不得导致应用崩溃。
- 自动检测使用仓库内版本化语料持续回归；规则修复必须保留对应误判样例。

## 10. 成功指标

由于首版是个人开源项目，不以注册或收入为指标：

- 核心任务完成率：测试用户成功完成粘贴、识别和复制的比例不低于 95%。
- 自动识别准确率：标准评测样例集不低于 95%，高置信度误转换率低于 1%。
- 结果正确率：受支持格式的合法样例解析与格式化通过率为 100%。
- 性能：达到第 7 节的 1 MB 与 10 MB 延迟目标。
- 稳定性：发布候选版本的核心样例与异常样例无崩溃。
- 开源验证：发布后优先观察有效 Issue、重复使用反馈和外部贡献，而非单独追求 Star 数量。

## 11. 风险与应对

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| Base64 与普通文本误判 | 用户看到错误结果 | 严格校验、可读性评分、低置信度只建议、保留原文。 |
| YAML 与普通文本/JSON 边界模糊 | 自动类型错误 | JSON 优先；YAML 设置最低结构特征；提供手动覆盖。 |
| CSV 分隔符和表头推断错误 | 表格错列 | 展示推断结果并允许手动切换分隔符与表头。 |
| 10 MB 内容阻塞界面 | 体验差或崩溃 | 后台解析、任务取消、输入防抖、结果虚拟化。 |
| XML/YAML 解析安全问题 | 本地数据泄露或代码执行 | 禁用 XML 外部实体；YAML 使用安全模式；加入恶意样例测试。 |
| 用户误把 MD5/SHA-1 当作安全算法 | 产生错误的安全设计 | 明确弱算法警告；文档推荐 SHA-256/384/512 或对应的 HMAC。 |
| HMAC 密钥意外残留 | 敏感信息泄露 | 不保存、不写日志；默认遮罩；关闭计算面板即清空。 |
| Windows/macOS 行为不一致 | 维护成本上升 | 共享核心处理层，并按手工发布清单在两个原生平台执行构建与冒烟测试。 |
